# 长篇工坊 2026.11.14.1

一个致力于帮助严肃文学新手的AI辅助工具。

本软件需用户自行配置 API。Windows x64 本地小说工作台，写手、审稿、定稿评论三个角色可分别配置服务商和模型。

## 下载

[Windows x64 便携版 2026.11.14.1](../../releases/download/v2026.11.14.1/NovelWorkshop_2026.11.14.1_Windows_x64.zip)

## 开始使用

1. 关闭旧版的程序窗口与网页，将压缩包完整解压到一个文件夹。
2. 双击 `NovelWorkshop_2026.11.14.1.exe`，保留启动窗口。程序内含 Python 和 SQLite，无需另装 Python。
3. 默认浏览器打开工作台。页面左上角应显示 `2026.11.14.1 · 本软件需用户自行配置API。`。首次使用进入空白的「我的小说」，已移除内置演示。
4. 展开「模型与 API 设置」，分别填写写手和审稿配置并应用。定稿评论模型可留空。新建或读取项目，填写章节卡，然后生成正文。

旧项目仍在原来的本机数据目录中，更新不要求重新导入。默认数据目录为 `%LOCALAPPDATA%\NovelWorkshop`；项目自己的保存目录可在页面修改。旧演示不再出现在列表，历史演示数据库不会被物理删除。

## 本版更新

- 项目栏新增「重命名项目」弹窗，手动保存文件使用 `项目名.novelproj`。重复项目名和 Windows 不支持的文件名会提示修改，避免覆盖其他文件。
- 页面打开时，当前项目每 30 分钟生成一次完整自动保存；繁忙时等待当前写作、审稿等操作结束再执行。自动保存包含当前未提交的编辑，保留最近两份。
- 服务商新增「自定义 · 完整 API 地址」与「小米 · MiMo」。完整地址支持公网、内网域名与本机 HTTP/HTTPS，可选择 Chat Completions、Responses 或 Messages 协议。
- 顶部可选择 Word DOCX、TXT、Markdown、RTF、HTML，再点「导出定稿」。只导出已确认定稿的章节，文件名采用项目名称；正文仍然可编辑。
- 顶部新增「夜晚模式」，再次点击「常规模式」恢复。空白项目、编辑区、审稿区、模型设置、评论区及弹窗均使用对应配色。
- 深绿色底、米白色宋体“文”字图标。根目录的 `icon.ico` 可更换。
- 两条引文在当前正文中明确对应同一位置时，仅显示一条；不同章节或重复段落造成位置歧义时保留两条。定位支持空白、常见引号和全角标点差异。忙碌期间也可定位当前正文；找不到时明确提示，不改动文本。
- 界面文字更新为「评论者人设」「定稿评论模型」「本章内容与篇幅」；新建项目名称输入框不再显示原来的示例。

## 保存、自动保存与恢复

在「本项目保存目录」填写绝对路径，例如 `D:\小说项目\我的小说`，点击「应用保存目录」。应用目录前，草稿数据库会完整复制到新目录，旧数据库留作恢复副本。已有同名数据库时拒绝覆盖。

「保存项目到本地」直接写入此目录的 `项目名.novelproj`，不会使用浏览器下载目录。同一项目后续手动保存更新该文件。工作数据库的内部标识保持稳定，不用手动改名。

自动保存文件形如 `项目名_20261114_153000_123456_自动保存.novelproj`。计时从页面打开该项目后开始；到时如果正在生成、改稿、审稿、评论或操作项目，会等待操作结束。电脑休眠或浏览器暂停时不会运行，恢复后补做已到期的保存。每次成功保存后重新计时 30 分钟。保存失败会显示原因并在一分钟后重试。页面关闭后不再运行计时器，已提交到本地数据库的稿件仍然保留。

每个项目由程序管理的自动保存最多两份，轮换时清理较早的一份；手动保存不参与轮换。程序只清理自己记录且仍属于本项目的文件，不删除同目录下其他手工备份。更换目录后，后续自动保存写入新目录，仍按该项目最近两份轮换。重命名也会更新程序管理的已有保存文件名；历史快照内部记录保留保存时的项目名，下一次保存写入新名称。

从「从本地读取项目」选择手动或自动保存的 `.novelproj`，均可恢复。读取创建独立副本并追加“（导入）”，多次导入会自动区分名称。文件包含规则、风格、审稿要求、章节卡、全部稿件版本、审稿、台账、定稿、评论及对话、自动审查设置、评论者人设和未提交编辑，不包含 API 密钥。恢复未提交编辑后仍需按对应按钮保存，不会自动定稿。

删除项目需要确认。删除后从列表移除，数据库和已有导出文件保留，便于恢复；删除最后一个项目后可重新新建或读取项目。

## 模型与连接

每个角色独立选择服务商、模型 ID、地址和密钥；可从服务商获取模型列表，也可手填模型 ID。选择后点击「应用设置」或「应用并测试连接」。评论模型 ID 留空不会妨碍写作和审稿。模型设置在本机共享，项目文件不带走连接配置；密钥仅在当前程序运行期间保留，重启后需重新输入。

普通服务商选项填写 Base URL；程序按对应协议补上请求路径。自定义完整地址选项填写**最终请求地址**，不会再添加、删除或改写路径及查询参数。例如：

- `http://localhost:1234/v1/chat/completions`
- `http://intranet-ai:8000/my/gateway?route=chat`
- `https://your-provider.example/api/responses`

完整地址模式请选择与服务端匹配的协议并手动填写模型 ID；程序不会猜测模型列表地址。无需鉴权的服务可留空密钥。地址必须是 HTTP 或 HTTPS，不能包含用户名、密码或 `#` 片段；中文路径需使用 URL 编码。程序直连所填地址，不回退到其他服务商，不跟随重定向。

MiMo 预设使用 `https://api.xiaomimimo.com/v1` 的 Chat Completions 接口与 `api-key` 鉴权。模型 ID 以账号实际可用列表为准；其他专用套餐或网关地址可使用完整自定义项，并按服务端要求选择协议。

MiMo 官方接入说明：https://mimo.mi.com/docs/en-US/quick-start/summary/first-api-call

## 写作与审稿

章节卡包括「本章内容与篇幅」和「行文节奏」。写手按本章要求安排详略、推进与停顿，不机械延续上一章的情绪和叙述方式。规则、写作风格、审稿要求按项目分别保存；改变规则、风格、节奏、参考定稿后，相关旧审稿会标记过期。

正文下方「自动审查」默认选中，可按项目关闭。生成或改稿后总是先保存并显示正文，再按复选框决定是否审稿。手工保存不自动审稿。自动审稿失败时正文和版本保留，可点「审查当前版本」重试。审稿期间正文只读，但可以阅读、复制和使用引文定位。

审稿默认检查章内逻辑、疑似 AI 痕迹、行文节奏，并加入作者填写的额外要求。疑似 AI 痕迹属于语言风格判断，不是作者身份鉴定。模型返回格式不完整、声称未收到正文或连接暂时失败时，审稿会使用同一完整正文有限重试；不会让写手重新生成，也不会静默覆盖成功的旧报告。

勾选想采纳的审稿意见，填写改稿指令并改稿。定稿前核对正文和台账；仍有审稿问题时，需明确勾选人工接受后才能定稿。

## 定稿评论

评论模型可留空。配置后，所有已有章节均已定稿、且没有未定稿的新版本时，页面底部的「评论现有定稿」按钮可用。评论只在点击时运行，依据现有定稿正文和「评论者人设」，不发送规则、章节卡、审稿或未定稿。

有评论后显示回复框与删除按钮，可以继续对话。失败保留输入和已有评论。删除须二次确认，确认后删除当前评论与全部对话，保留正文及评论者人设。新的人设用于下一次生成评论；已有对话沿用生成时的人设。定稿有变化时，评论显示过期，重新评论后继续对话。

## 更换图标

用你自己的 ICO 文件替换根目录 `icon.ico`，重启程序并刷新页面，页面图标、浏览器图标和支持设置图标的启动窗口会使用新图标。建议 ICO 同时包含 16、32、48、256 像素尺寸。文件不是把 PNG 扩展名直接改成 ICO。

EXE 文件自身包含本版“文”字图标；Windows 文件管理器显示的 EXE 内嵌图标不会因外部 ICO 改动而自动重写。如希望启动入口也使用可更换图标，双击根目录 `CreateShortcut.vbs`，它只在当前目录生成 `NovelWorkshop.lnk`，图标指向同目录的 `icon.ico`。替换 ICO 后可重新生成快捷方式；Windows 若缓存旧图标，刷新文件夹或重新登录后查看。

## 源码与验证

`source` 目录包含源码、测试和打包脚本；源码运行需 Python 3.10+，无需第三方运行依赖。构建 Windows 包需 CPython 3.13，可复用之前版本中的 Windows 运行库：

```text
python3.13 source/build_windows.py --reuse-runtime OLD.exe NEW.exe
python3.13 -m unittest discover -s source -p "test_*.py"
node source/test_interface.cjs
python3.13 source/verify_release.py NEW.exe
```

本次验证包括后端回归、真实本地 HTTP 与页面脚本事件测试、完整 API 地址请求、自动保存轮换与互斥、定稿导出、Word 样本渲染检查和 Windows 包结构与图标资源检查。测试模型使用模拟服务；未在原生 Windows 上运行 EXE，也未使用真实服务商密钥进行收费调用。页面脚本测试不等于真实浏览器视觉测试。
